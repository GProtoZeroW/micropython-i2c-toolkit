# micropython-i2c-toolkit

A PyVISA-style connection layer over MicroPython's `machine.I2C`, with drivers, a
declarative mux-aware routing table, and bring-up notebooks for the
[micropylab](../micropylab) Jupyter kernel.

You resolve a device once to a `(bus, mux path, address)` handle, and from then on the
handle is the device: addressing, mux routing and per-bus locking are its job, not the
driver's.

```python
from micropython_i2c import I2CConnection, default_lock
from micropython_i2c.boards import bus_open
from micropython_i2c.devices.sensors.environmental.tmp102 import TMP102

bus = bus_open("feathers3", 0)
tmp = TMP102(I2CConnection(bus, 0x48, path=[[0x71, 3]], lock=default_lock()))
print(tmp.temperature())
```

  connection.py           I2CConnection, path_select / path_release
  node.py                 I2CNode -> I2CDevice | I2CMux
  bits.py, crc.py         BitTools, CRCMixin
  protocol.py             RegisterI2CBase, CommandI2CBase
  routing.py              RoutingTable, ConfigError
  manager.py              I2CManager, scan_check
  boards.py               board pin maps, bus_open()
  debug.py                show / check helpers for notebooks
  sim/                    host only: SimClock, signals, FakeBus, SimBench (see Simulation)
  devices/                lazy registry (DRIVERS, FAKES) over the parts, by type; each
                          part's fake sits next to its driver as <part>_fake.py
    sensors/              by kind:
      environmental/      TMP102 (temperature), SHTC3 (humidity, temperature)
      magnetic/           TMAG5273 (3-axis Hall)

                          connection, node, protocol, routing, boards, manager, devices
                          (registry), package_inits, and sim_clock, sim_signals, sim_bus,
                          sim_bench (host only)
device_notebooks/         sources of the device modules and their fakes, by type (same tree
                          as devices/). Each writes the fake, the driver and their tests,
                          runs them on the host, then checks the real part
  sensors/environmental/tmp102_devNB, shtc3_devNB
  sensors/magnetic/tmag5273_devNB
  sensors/distance/vl53l1x_devNB, vl53l4cd_devNB
  muxes/tca9548a_devNB
  drivers/qwiic_relay_devNB   (MCP23017 to come)
notebooks/                whole-bench hardware checks
  03_routing_harness      the whole bench: rehearsed in simulation, then config ->
                          validate -> scan -> build -> talk on the board
  bench.json              the bench's routing config, shared by both

## Setup

micropylab must be checked out next to this repo (`../micropylab`); it is installed
editable from there.

```bash
uv sync                       # host tools: JupyterLab, micropylab kernel, jupytext, ruff, pytest
uv run jupyter lab
```

Open a notebook, pick the **MicroPython (micropylab)** kernel, and run it top to bottom.
Each notebook's first cells connect (`%board connect`) and copy the package to the board
(`%files copy -r src/micropython_i2c :/lib/micropython_i2c`). Re-run those two cells
after editing the package; the import cell drops stale modules so the new files load.

To ship compiled bytecode instead, `%files compile src/micropython_i2c/<mod>.py
/lib/micropython_i2c/` per module, and delete the matching `.py` on the board: when both
exist, MicroPython imports the `.py`.

## Tests and lint

Every source file is generated by a notebook (jupytext `.py` is the source of truth; edit the
notebook, not the file). Each notebook runs on the host first: everything above
`%board connect` runs in ordinary Python on this computer, against fake parts. After
`%board connect`, cells run in MicroPython on the board, except `%%host` cells.

The package imports on CPython, so everything that does not need silicon is tested on the
host against the fakes (`sim.bus.FakeBus` models mux routing the way real hardware does):

```bash
uv run pytest
uv run ruff check
```

The notebooks are the hardware tests. Each ends with a PASS/FAIL tally.

## Simulation

A whole project can run on the host with no hardware, in simulated time:

```python
from micropython_i2c.sim.bench import SimBench
from micropython_i2c.sim.clock import SimClock
from micropython_i2c.sim.signals import ramp

with SimClock() as clock:                  # sleeps return at once; time moves only on a sleep
    bench = SimBench(CONFIG, parts={"temp": {"temp_c": ramp(20.0, 26.0, 0, 3600)}}).build()
    clock.advance(1800)
    bench["temp"].temperature()            # about 23 C, through the real manager and driver
```

`CONFIG` is the same routing config the real bench uses. Each part's quantities can be plain
values or signals (`ramp`, `step`, `sine`, `sequence`, `noisy`, `lag`, or any `f(t_s)`), and a
signal can read another fake (a heater relay's state). `dev_notebooks/sim_bench_devNB` runs a
greenhouse controller (thermostat, door magnet, visitor) for three simulated hours in about
0.1 s. What it cannot show: RAM on the board, timing on the wire, or anything electrical.

## Adding a driver

See "Writing a driver" in [docs/design.md](docs/design.md). In short: a `<Part>Regs`
facts-only class plus a driver deriving from it, codecs as classmethods with offline
tests, a fake (`<part>_fake.py`) written in the same device notebook, and entries in
`devices.DRIVERS` and `devices.FAKES` (`dev_notebooks/devices_devNB`).
